ㅇㄱㅁㅇ v18 — 방문객이 이해하기 쉬운 말로 바꾸기

이번 단계는 화면 용어·문장·안내 순서를 다듬는 작업입니다.
방문객 사용 시험은 아직 진행하지 않았습니다.
이미 준비한 관찰 장소와 QR 주소는 그대로 사용할 수 있습니다.

1. 달라진 말
이전                           현재
숲 관찰                        숲 둘러보기
기관 변경                      숲체원 바꾸기
사진 기록(아래 메뉴)            식물 찾기

관찰 기록 내려받기(.txt)        기록 파일 받기
AI 식물 후보 분석              사진 속 식물 알아보기
이 후보 선택                   이 이름 고르기
계정에 비공개 저장              내 도감에 저장하기

공유 철회                      공유 취소

- 저장 버튼 옆에는 ‘나만 볼 수 있어요’, ‘같은 아이디로 다른 기기에서도 볼 수 있어요’를 설명합니다.
- AI가 알려주는 식물 이름은 틀릴 수 있다는 안내를 유지합니다.
- 학명과 AI 점수는 ‘다른 이름과 AI 점수 보기’를 펼쳤을 때 보여줍니다.
- 이름을 고르는 버튼은 즉시 저장하는 기능이 아니므로 ‘이 이름 고르기’로 표현합니다.
- 공유 담당자의 확인이 식물 이름의 정확성을 보장하지 않는다는 안내를 쉬운 말로 유지합니다.
- 사진을 외부 식물 찾기 서비스 Pl@ntNet으로 보낸다는 안내와 동의는 유지합니다.

2. 숲 둘러보기 화면
- ‘설명 읽기 → 나무 살펴보기 → 한 줄 남기기’를 첫 화면에 보여줍니다.
- 글이 자동으로 저장되지 않는다는 안내와 기록 파일 받는 방법을 눈에 띄게 표시합니다.
- 글이 지워지는 경우는 ‘언제 글이 지워지나요?’에서 확인할 수 있습니다.
- 학명, 설명 자료, 화면에 등록된 확인 정보는 자세히 보기로 옮겼습니다.
- 식물 설명의 ‘기공선’은 ‘숨구멍이 모여 만든 흰 선’으로 풉니다.
- 굴참나무는 ‘두껍고 갈라진 나무껍질’로 특징을 안내합니다.
- 사진 없이 쓴 글도 모아서 볼 수 있고, 전체를 모두 찾지 않아도 됩니다.
- 읽기 편하도록 주요 안내와 식물 설명의 글자 크기를 조금 키웠습니다.

3. 이미 준비한 자료를 지키는 방법 — 먼저 읽어주세요
이번 ZIP의 src/experience-data.js는 v17 원본과 동일합니다.
하지만 사용자의 PC에서 나무 위치·사진·설명을 따로 입력했다면 그 파일은 ZIP과 다를 수 있습니다.
새 파일을 복사할 때 아래 항목은 자신의 기존 파일을 유지하세요.

- public-config.json: 현재 Firebase와 AI 주소 설정
- src/experience-data.js: 직접 작성한 나무 설명·사진 경로·관찰 장소·확인 정보
- public/experience 폴더 등 직접 추가한 사진 파일
- .git 폴더: 기존 GitHub 연결과 변경 이력

새 src/easy-language.js 파일은 반드시 함께 복사하세요.
기본 v17 식물 설명의 알려진 문장만 화면에서 쉽게 풀어 보여줍니다.
사용자가 따로 쓴 설명이나 사진·위치·학명·확인 정보는 이 기능이 바꾸지 않습니다.
다만 따로 작성한 설명의 어려운 말은 담당자가 직접 확인하여 바꿔주세요.
화면 용어가 바뀌어도 기존 체험 주소의 center와 view 값은 바뀌지 않습니다.
QR 코드를 다시 만들 필요는 없습니다.

4. Windows 적용 순서
(1) 기존 프로젝트 폴더 전체를 다른 폴더에 복사하여 백업합니다.
(2) 이번 ZIP을 별도 임시 폴더에 먼저 압축 해제합니다.
(3) 새 파일을 기존 프로젝트에 복사하되, 위 3번의 파일과 사진은 유지합니다.
    전체 폴더를 지우고 새 ZIP으로 대체하지 마세요.
    node_modules 폴더는 복사하지 않습니다.
(4) 프로젝트 루트의 명령 프롬프트(cmd)에서 실행합니다.
    cd /d "C:\Users\김준태\Documents\GitHub\bangjangsan-plant-book"
    npm ci
    npm test
    npm run build
    firebase deploy --only hosting --project plant-book-84803
(5) 기존 QR 주소를 휴대폰에서 열어 변경한 말과 버튼을 확인합니다.
(6) GitHub Desktop에서 Commit 후 Push origin으로 변경을 올립니다.

기존 v17이 정상 동작했다면 Firebase 규칙·인덱스·Cloudflare Worker·비밀 키·Spark 요금제는 그대로입니다.
이번에는 Hosting만 배포하면 됩니다. Firebase init은 다시 실행하지 마세요.
회사 PC에서 인증서 설정이 필요했다면 같은 cmd 창에서 먼저 실행합니다.
    set "NODE_USE_SYSTEM_CA=1"
기존 기기 기록을 지킬 수 있도록 브라우저 데이터 삭제는 업데이트 방법으로 사용하지 마세요.

5. 배포 후 본인이 먼저 확인할 것
- 기존 QR로 숲 둘러보기가 열리는지.
- 설명 읽기, 살펴본 표시, 글 작성, 내 기록 보기, 기록 파일 받기가 이해하기 쉬운지.
- 새로고침·창 닫기·다른 숲체원 선택·로그인/로그아웃 시 임시 방문객 글이 사라진다는 안내가 보이는지.
- 식물 찾기는 로그인 후 이용하며, 내 도감 저장과 이름 선택이 다른 동작임을 알 수 있는지.
- 함께 보기에서 다른 사람의 기록을 볼 수 있고, 내 기록을 공개하려면 따로 동의와 요청이 필요한지.
- 이미 등록한 나무 위치, 사진, QR 주소, 설명이 유지됐는지.

이번 버전으로 바로 방문객 사용 시험을 진행할 필요는 없습니다.
먼저 표현과 화면을 확인하고 추가로 바꿀 부분을 모은 뒤 시험하면 됩니다.

6. 개발 확인
- 기존 동작 검사와 설명 변환 자료 보존 검사를 수행했습니다.
- Windows 경로 수정본을 유지하며 한글·공백 경로에서도 체험 화면 테스트를 확인합니다.
- 최종 결과는 verification/unit-v18.txt, build-v18.txt, static-v18.txt에 기록합니다.
