v32 — 지도에서 나무 위치를 등록하고 방문객에게 보여주기

달라진 이용 방법
숲 둘러보기의 나무 지도 탭을 엽니다.
방문객: 지도 열기 → 나무 표시 또는 이름 선택 → 사진 2장·장소·관찰 질문 확인.
사진 아래 나무 지도에서 찾기 버튼으로도 지도 화면을 열 수 있습니다.
이전 소스 좌표의 외부 지도 링크를 나무 카드에서 바로 노출하지 않고 나무 지도에서 최신 위치를 확인하도록 연결했습니다.
담당자: 내 도감에서 로그인 → 숲 둘러보기 → 나무 지도 → 나무 선택 → 지도에서 나무 위치 고르기.
숫자 좌표를 직접 입력할 필요가 없습니다.

처음 한 번 필요한 작업
A. 카카오 지도 JavaScript 키와 접속 도메인 설정
B. 기존 Firebase 프로젝트에 새 Firestore 규칙 배포
C. 화면 빌드·Hosting 배포
기관 담당자 권한을 이미 부여했다면 같은 권한을 사용합니다.
위 작업은 아래에서 차례로 설명합니다.

A-1. 카카오 개발자 앱 준비
1. https://developers.kakao.com 에서 카카오 계정으로 로그인합니다.
2. 앱 메뉴에서 기존에 이 서비스용으로 만든 앱을 선택하거나 새 앱을 만듭니다.
3. 앱 이름은 예를 들어 ㅇㄱㅁㅇ로 설정합니다. 소유 주체 정보는 실제 운영 주체에 맞춥니다.
4. 앱의 카카오맵 → 사용 설정에서 상태를 ON으로 설정합니다.
5. 카카오의 무료 할당량과 추가 쿼터 설정을 확인합니다. Firebase Spark와 카카오 쿼터는 별개입니다.

A-2. JavaScript 키·도메인 등록
1. 앱 설정 → 앱 → 플랫폼 키에서 JavaScript 키를 선택합니다.
   화면 개편에 따라 메뉴명이 조금 다르면 JavaScript 키 설정 화면을 찾습니다.
2. JavaScript SDK 도메인에 실제 접속 주소를 등록합니다.
   https://plant-book-84803.web.app
   https://plant-book-84803.firebaseapp.com
3. PC의 npm run preview로 확인한다면 아래도 등록합니다.
   http://127.0.0.1:4173
   http://localhost:4173
4. 주소 뒤에 /index.html, 경로, ?center=... 같은 검색값을 넣지 않습니다.
5. JavaScript 키를 복사합니다. REST API 키나 Admin 키를 사용하지 않습니다.

A-3. 프로젝트 설정에 키 넣기
기존 public-config.json의 Firebase·identifyEndpoint 설정은 유지하고,
최상위에 kakaoMap 항목을 추가합니다. 새 ZIP에는 빈 항목이 이미 있습니다.

  "kakaoMap": {
    "javascriptKey": "복사한 JavaScript 키"
  }

기존 마지막 항목과 kakaoMap 사이에는 쉼표가 있어야 합니다.
예를 들어 마지막 부분은 다음 모양입니다.

  "identifyEndpoint": "https://forest-plant-identify.plant-book.workers.dev/identify",
  "kakaoMap": {
    "javascriptKey": "복사한 JavaScript 키"
  }
}

파일 앞쪽의 firebase, emulators 항목을 지우지 마세요.
JavaScript 키는 웹페이지에서 사용하는 공개 키입니다. 허용 도메인을 제한해서 사용합니다.
Pl@ntNet 비밀키나 카카오 Admin/REST 키를 이 항목에 넣지 마세요.

B. Firebase 규칙 적용
기존 프로젝트를 백업하고 새 ZIP의 코드를 적용합니다.
본인 public-config.json, backend/wrangler.jsonc, .firebaserc(있을 때), .git,
src/experience-data.js와 본인이 추가한 자료를 보존합니다.
src/observation-places.js에서 기관 ID·장소를 수정했다면 그 설정 값도 유지합니다.
새 firestore.rules를 적용하고 프로젝트 루트 터미널에서 실행합니다.

npm ci
npm test
npm run build
firebase deploy --only firestore --project plant-book-84803
firebase deploy --only hosting --project plant-book-84803

이번 버전은 Hosting만 배포하면 위치 저장이 거부됩니다. 규칙을 먼저 배포하세요.
기존 규칙을 직접 수정했다면 새 treePlaces 규칙과 변경 내용을 비교해 합칩니다.
새 복합 인덱스는 필요 없습니다. Firebase init과 Worker 재배포는 하지 않습니다.

C. 담당자 권한 확인
1. 기존 이메일·비밀번호 계정으로 내 도감에서 로그인합니다.
2. Firebase의 forestReviewerGrants/{담당자UID}/centers/{기관ID}에 active: true가 있어야 합니다.
3. forestCenters/{기관ID}도 active: true여야 합니다.
4. 권한이 없다면 CENTER_AND_REVIEWER_SETUP.txt의 담당자 등록 절차를 따릅니다.
방문객·일반 계정·다른 기관 담당자·익명 로그인은 위치를 수정할 수 없습니다.

D. 나무 위치 등록 (숫자를 입력하지 않는 방식)
1. 장성숲체원을 고르고 숲 둘러보기 → 나무 지도를 엽니다.
2. 지도 열기를 누릅니다.
3. 숲체원·건물 찾기에 국립장성숲체원 등 실제 장소를 적고 지도 이동을 누릅니다.
4. 검색 결과의 이름·주소를 확인해 원하는 곳을 선택합니다.
   검색은 지도를 옮기기만 하며, 나무 위치를 저장하지 않습니다.
5. 편백나무·갈참나무·단풍나무 중 하나를 고릅니다.
6. 담당자 위치 관리 → 지도에서 나무 위치 고르기를 누릅니다.
7. 지도를 확대·이동해 실제 나무를 관찰할 수 있는 지점을 누릅니다.
   지도 가운데 표시를 맞춘 뒤 지도 가운데를 위치로 선택을 눌러도 됩니다.
8. 임시 표시와 장소 설명을 확인합니다.
   편백나무·갈참나무: 숙소동1 부근 난간 근처
   단풍나무: 숙소동2에서 숲누림길로 올라가는 시작점
9. 모든 방문객에게 공개하는 동의 항목에 표시한 뒤 이 위치 공개하기를 누릅니다.
10. 다른 브라우저에서 로그아웃한 상태로 같은 기관의 나무 지도를 열어 확인합니다.

같은 구역의 두 나무도 위치는 각각 선택합니다. 임의로 좌표를 복사하지 않습니다.
지도를 누르거나 장소를 검색하기만 해서는 저장하지 않습니다.
화면을 나갈 때 저장 전 선택이 있으면 확인하고, 새로고침 때도 경고합니다.
선택 중 위치는 영구 저장하지 않으므로 작업을 마친 뒤 공개 버튼을 누르세요.

수정·공개 해제
같은 나무를 고른 뒤 다시 위치를 선택·확인·공개하면 수정됩니다.
공개 위치 지우기는 지도 표시만 지우고 사진과 장소 설명은 유지합니다.
다른 담당자가 먼저 수정했다면 저장을 거부하고 다시 불러오도록 안내합니다.
통신 오류로 결과가 불확실하면 나무 위치 다시 불러오기로 서버 상태를 먼저 확인합니다.
다시 불러오면 저장 전 선택을 버릴지 묻습니다.
기존 소스의 좌표가 있어도 서버에서 지도 표시를 지운 나무는 다시 표시하지 않습니다.

저장 구조
공개 관찰 장소: forestCenters/{기관ID}/treePlaces/{나무ID}
나무ID: hinoki / galcham-oak / japanese-maple
내용: 장소 설명, 지도 좌표(또는 공개 해제 null), 수정 번호, 서버 수정 시각.
방문객의 이메일·개인 메모·GPS 사진 기록은 이 문서에 넣지 않습니다.
기관 담당자가 등록하는 공개 관찰 위치이며 방문 인증이나 종 확정이 아닙니다.
방문객이 발견한 구역을 직접 공유하는 기능은 아직 추가하지 않았습니다.

지도와 목록
모바일은 지도 아래, PC는 지도 옆에 선택한 나무 정보를 보여줍니다.
지도 표시를 누르기 어려우면 나무 이름 버튼으로도 같은 정보를 확인할 수 있습니다.
지도 확대·축소, 방향 이동, 가운데 선택 버튼은 키보드로도 누를 수 있습니다.
기존 네 개의 하단/상단 메뉴는 유지합니다. 나무 지도는 숲 둘러보기 안에 있습니다.
지도 키가 비어 있거나 로딩이 실패해도 기존 사진·장소 설명·도감 기능은 유지합니다.
실제 좌표는 아직 등록하지 않았으므로 처음에는 나무 표시가 없습니다.

문제 해결
- 지도 준비 중: public-config.json의 JavaScript 키를 확인하고 다시 빌드·배포합니다.
- 지도 로딩 오류: 카카오맵 사용 설정 ON, 접속 도메인, JavaScript 키 종류, 네트워크를 확인합니다.
- 지도 저장 권한 오류: 새 Firestore 규칙, 담당자 권한, 기관 active 상태, 이메일 로그인 확인.
- 기관이 다르게 나옴: 기관을 다시 선택하고 권한 문서의 기관 ID를 비교합니다.
- 위치가 틀림: 담당자 계정에서 지도를 확대해 다시 선택한 뒤 공개합니다.
- 타일이 안 보임: 보안 헤더도 새 빌드로 배포했는지 확인하고 브라우저 개발자 도구의 차단 도메인을 확인합니다.
보안 헤더는 지도 SDK·지도 이미지·검색에 필요한 호스트를 허용했습니다.
외부 요청의 기본 referrer는 출처 도메인만 전달하도록 설정했으며, 사적인 경로·검색값은 전달하지 않습니다.

확인 범위
자동 검사에서는 SDK 어댑터·클릭·동의·계정 전환·규칙과 실제 Firestore 저장을 검증했습니다.
카카오 실서비스의 타일/키/도메인 동작과 실제 휴대폰 화면은 사용자 설정 후 확인해야 합니다.
