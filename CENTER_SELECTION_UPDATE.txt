ㅇㄱㅁㅇ v13 — 관찰 숲체원 선택과 기록·공유 연결
작성일: 2026-10-16

현재 이용 흐름
기관 선택 → 사진 기록(필요하면 로그인) → AI 후보 비교 → 기록 저장 → 선택 기관에 공유 신청.
기관 선택은 방문 장소 선택입니다. 직원 소속이나 담당자 권한을 부여하지 않습니다.
GPS 자동 판정은 사용하지 않으며, 사용자가 목록에서 관찰할 기관을 직접 선택합니다.

새 기능
- 첫 화면에서 Firestore forestCenters에 등록된 active=true 기관을 선택합니다.
- 최근 선택 기관 ID를 이 브라우저에만 기억하고, 다시 접속하면 시작 화면에서 확인합니다.
- 선택한 기관을 상단에 표시하고 '기관 변경'으로 바꿀 수 있습니다.
- 새 계정 기록에 centerId와 centerName을 함께 저장합니다.
- 사진 기록의 기관 이름을 수동 입력하지 않아도 됩니다.
- 공유 도감의 공개 목록·공유 신청·신청 상태·담당자 검토가 선택한 기관을 따릅니다.
- 새 기관 ID가 있는 기록은 같은 기관으로만 공유 신청할 수 있습니다.
- 처리 중이거나 상세창이 열려 있으면 전역 메뉴 이동을 제한합니다.
- 작성 중 다른 화면/기관으로 이동하면 초기화 확인을 거칩니다.
  내 도감과 사진 기록 사이 이동은 작성 내용을 유지합니다.

기존 기록과 수정
기존 개인 기록과 사진은 삭제/일괄 변경/자동 이관하지 않습니다.
내 도감은 모든 기관의 개인 기록을 함께 보여주며 각 기록에 기관 이름을 표시합니다.
기관 ID가 없는 기존 기록은 '이전 기록'으로 공유 선택 목록에 표시됩니다.
공유 신청 전에 수기 기관 이름과 현재 공유 기관이 맞는지 직접 확인해야 합니다.
기존 기록을 실제로 방문하지 않은 다른 기관에 제출하지 마세요.
기관 ID가 있는 기록의 관찰 기관을 고치려면 내 도감 상세 → 계정 기록 수정 → 기관 선택을 사용합니다.
기관 수정은 기존 공유를 철회하며, 새 기관으로 다시 공유 신청하고 검토받아야 합니다.
비활성 기관에서 과거에 저장한 개인 기록도 메모 수정/삭제가 가능합니다.
기관 선택은 정확한 관찰 GPS를 자동 생성하지 않습니다. 위치 기록은 기존 선택 방식입니다.

기관 목록이 한 곳만 보일 때
프로그램은 전국 기관을 자동 생성하지 않습니다.
Firebase 콘솔 forestCenters에 등록된 활성 기관만 목록에 나타납니다.
현재 장성만 등록했다면 장성만 보이는 것이 정상입니다.
다른 기관도 CENTER_AND_REVIEWER_SETUP.txt의 같은 방식으로 등록합니다.
각 기관에 별도 ID를 사용하고 name, active, mapCenter, isDemo를 입력합니다.
알 수 없는 기관 위치를 임의 좌표로 넣지 말고 mapCenter=null로 둡니다.
시연을 위한 가상 기관은 이름에 시연용을 표시하고 isDemo=true를 사용하세요.
가상 기관에서 실제 운영한 것처럼 발표하지 않습니다.
기관 담당자 권한도 해당 기관 ID로 별도 부여합니다.
추가한 뒤 앱의 '기관 목록 새로고침'을 눌러 확인합니다.

로고 표시
첨부한 국립장성숲체원 로고는 하단에 '개발·시범 적용: 국립장성숲체원'으로 표시합니다.
다른 관찰 기관을 선택해도 장성 로고를 해당 기관 로고로 잘못 표시하지 않습니다.
기관별 로고 자동 교체는 이번 단계에 포함하지 않습니다.

적용 순서
1. 기존 프로젝트 전체, public-config.json과 별도로 수정한 Firestore 규칙을 백업하세요.
2. ZIP을 별도 폴더에 풀고 내용물을 기존 bangjangsan-plant-book 폴더에 덮어씁니다.
   기존 .git을 유지하고 폴더를 중첩시키지 않습니다.
3. 공개 Firebase 설정과 Worker 주소를 확인하세요. 앞서 확인한 값이 포함되어 있습니다.
   이후 변경한 설정이 있다면 자신의 설정을 유지하세요.
4. 아래 명령을 프로젝트 루트에서 순서대로 실행하세요.

cd /d "C:\Users\김준태\Documents\GitHub\bangjangsan-plant-book"
set "NODE_USE_SYSTEM_CA=1"
npm ci
npm test
npm run build
firebase deploy --only firestore --project plant-book-84803
firebase deploy --only hosting --project plant-book-84803

이번 버전에는 새 선택 기관 ID를 허용하고 공유 기관을 대조하는 규칙이 있습니다.
Firestore 배포가 성공했는지 확인한 다음 Hosting을 배포하세요.
별도로 수정한 현재 규칙이 있다면 백업하고 필요한 변경을 병합해야 합니다.
firebase init으로 기존 설정을 덮어쓰지 마세요.
기존 기관/담당자 문서를 삭제하거나 새로 만들 필요는 없습니다.

Cloudflare 서버
v12 서버를 이미 배포했다면 이번에는 Cloudflare를 재배포하지 않아도 됩니다.
API 키를 다시 발급/입력하지 않습니다.
v11/v12 서버 배포를 건너뛰었다면 REFERENCE_PHOTOS_UPDATE.txt의 기존 서버 배포도 완료하세요.

휴대폰 점검
1. 첫 화면에서 기관 선택 후 시작 → 상단 기관 이름 확인.
2. 로그인 → 사진 선택/촬영 → 한글 이름/비교 사진 확인 → 새 기록 저장.
3. 내 도감에서 저장한 기관 확인, 다른 기기 같은 계정으로 확인.
4. 공유 도감에서 동일한 기관의 공개 목록과 공유 신청 확인.
5. 다른 등록 기관으로 변경해 공개 목록/담당자 검토 범위가 바뀌는지 확인.
6. 작성 중 기관 변경을 눌러 초기화 확인 문구와 취소 동작 확인.
7. 이전 기기 기록/백업은 첫 화면의 '이 기기에 저장한 기록 먼저 보기'로 확인.
8. 재접속 시 최근 기관이 선택되어 있고 시작 버튼으로 확인할 수 있는지 확인.

검증 범위
앱 단위 테스트 50개, Firestore 에뮬레이터 규칙 테스트 29개와 빌드를 확인했습니다.
규칙 검사는 새 기관 ID의 유효성, 다른 기관으로의 공유 거부, 기존 기록 호환,
기관 수정 시 공유 철회, 기존 공개·검토·개인 기록 접근 통제를 포함합니다.
React 서버 렌더링으로 첫 기관 화면·복수 선택지·공유 기관 표시를 확인했습니다.
실제 모바일 브라우저의 이동/확인창/키보드·카메라·GPS는 검증하지 못했습니다.
실제 Firebase/Cloudflare 배포나 AI 호출은 수행하지 않았습니다.

해커톤 시연 추천
기관 선택 → 장성에서 사진 분석/저장/공유 검토까지 시연합니다.
다른 등록 기관으로 바꾸어 기관별 목록/권한 분리도 보여줄 수 있습니다.
실제 시범 적용 범위와 시연용 데이터를 구분해서 설명하세요.
