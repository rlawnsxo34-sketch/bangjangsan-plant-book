ㅇㄱㅁㅇ v17 Windows 테스트 호환성 수정

이번 수정은 테스트 코드 두 파일에 적용합니다.
tests/experience-ui.test.mjs
tests/experience-routing.test.mjs

수정 내용
1. UI 테스트: 파일 URL의 pathname을 다시 pathToFileURL로 변환하던 코드를 제거하고, 원래 파일 URL의 href로 import합니다.
   Windows의 C: 드라이브 중복 및 한글·공백 경로의 이중 인코딩을 피합니다.
2. 라우팅 테스트: 테스트 서버 대체 코드의 esbuild 필터에서 Windows 역슬래시와 Linux 슬래시를 모두 처리합니다.
   대체 코드가 실제 적용되었는지 앱을 import하기 전에 확인해 실제 Firebase 연결이 발생하지 않도록 합니다.
3. 두 테스트 모두 실행한 현재 폴더에 의존하지 않도록 프로젝트 루트를 파일 URL에서 계산합니다.
4. 임시 모듈 파일은 import 실패 시에도 finally에서 정리합니다.

적용 방법
1. ZIP을 별도 폴더에 압축 해제합니다.
2. 위 두 파일만 현재 프로젝트의 tests 폴더에 복사하여 덮어씁니다.
   src, public-config.json, Firebase 설정을 수정할 필요가 없습니다.
3. 기존 프로젝트 루트의 cmd에서 실행합니다.
   npm test
4. 모두 통과하면 기존 v17 적용 작업을 이어갑니다.
   npm run build
   firebase deploy --only hosting --project plant-book-84803

이번 ZIP은 전체 프로젝트를 포함하지만 이미 v17을 적용했다면 테스트 두 파일만 바꾸면 됩니다.
이번 테스트 수정만을 위해 새 API 키 발급, Firebase 초기화, npm install을 다시 할 필요는 없습니다.
이미 v17을 배포했다면 이 수정만으로 웹사이트를 다시 배포할 필요도 없습니다.

계속 실패한다면 다음 명령으로 실행하고 맨 위 오류부터 끝까지 출력 전체를 전달해주세요.
node --test --test-reporter=spec tests/experience-routing.test.mjs tests/experience-ui.test.mjs
최종 'test failed' 두 줄만으로는 개별 환경의 추가 원인을 확인할 수 없습니다.

검증 결과
- Linux 환경에서 전체 테스트 84개 통과, 빌드 통과.
- 한글 및 공백을 포함한 별도 프로젝트 경로에서 두 파일의 7개 테스트 통과.
- Windows 및 Linux 경로 구분자에 대한 필터 일치 확인.
- 앱 소스, Firebase/Cloudflare 설정, 배포용 HTML은 원본 v17과 동일함을 확인.
- 실제 Windows OS에서 실행하지는 않았습니다. 사용자 PC에서 npm test 확인이 필요합니다.
