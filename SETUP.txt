처음부터 설정하는 방법 — Windows 명령 프롬프트(cmd) 기준
작성일: 2026-10-12

A. Firebase 프로젝트 열기
https://console.firebase.google.com/ 에 접속하고 기존 plant-book-84803 프로젝트를 엽니다.
이번 코드는 프로젝트의 요금제나 실제 배포를 자동으로 변경하지 않습니다.
Spark에서 Authentication(이메일/비밀번호)·Firestore·Hosting을 무료 한도 내 사용합니다.
이미 Blaze인 프로젝트의 요금제를 이 파일이 내리지는 않습니다.

B. 이메일 로그인을 켜기
Firebase 콘솔 → Authentication → 시작하기(이미 사용 중이면 생략)
→ 로그인 방법(Sign-in method) → 이메일/비밀번호 → 이메일/비밀번호 사용 → 저장.
'이메일 링크' 방식은 필요하지 않습니다.
계정은 앱의 '새 계정 만들기'에서 생성합니다. Firebase CLI 로그인 Google 계정과 별개입니다.
앱 계정 비밀번호를 소스 파일에 입력하지 마세요.
Authentication 설정의 승인된 도메인에서 배포 도메인을 확인합니다.
로컬 시험이 필요하면 localhost와 127.0.0.1 승인 여부도 확인합니다.
비밀번호 재설정 메일은 Firebase에서 전송하므로 메일 사용량 한도가 적용됩니다.

C. Firestore 준비
Firestore Database → 데이터베이스 만들기.
개발용 무료 한도를 사용하려면 Standard 에디션의 기본(default) 데이터베이스를 사용합니다.
프로젝트에 기본 DB가 이미 있으면 추가 DB를 만들 필요가 없습니다.
새로 만들 때 공개 테스트 규칙 대신 프로덕션 모드를 선택합니다.
위치는 기관의 데이터 관리 기준에 맞게 선택합니다. 처음 정한 데이터베이스 위치는 신중히 정합니다.
새 프로젝트의 위치 선택이 가능하고 기관 기준이 없다면 서울 지역(asia-northeast3)을 검토합니다.
데이터 화면에서 기록을 손으로 만들 필요는 없습니다. 앱이 기록과 사진 문서를 함께 생성합니다.

D. 웹 앱 공개 설정 가져오기
프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → 웹 앱(</>)의 SDK 설정/구성.
웹 앱이 없다면 웹 앱을 등록합니다. 이름은 식물 도감 등으로 지정해도 됩니다.
표시된 firebaseConfig에서 apiKey, authDomain, projectId, appId를 복사합니다.
프로젝트 폴더의 public-config.json을 메모장으로 열고 해당 값에 입력합니다.

예시(아래 값은 실제 설정이 아닙니다):
{
  "firebase": {
    "apiKey": "여기에 Firebase 웹 앱 apiKey",
    "authDomain": "plant-book-84803.firebaseapp.com",
    "projectId": "plant-book-84803",
    "appId": "여기에 Firebase 웹 앱 appId"
  },
  "emulators": { "enabled": false }
}

JSON의 큰따옴표와 쉼표를 유지합니다. firebaseConfig JavaScript 전체를 그대로 붙이지 않습니다.
Firebase 웹 앱 구성은 브라우저에서 사용하는 공개 식별 설정입니다.
접근 보호는 아래 Firestore 규칙에서 강제합니다. 서비스 계정 개인키는 넣지 않습니다.
Pl@ntNet 비밀 키는 아직 필요하지 않으며 이 파일에 넣는 자리도 없습니다.

E. 프로젝트 폴더에서 설치·빌드
cmd 실행 후:
cd /d "C:\Users\김준태\Documents\GitHub\bangjangsan-plant-book"
dir package.json firebase.json
npm ci
npm test
npm run build

설정 파일을 변경할 때마다 npm run build를 다시 실행해야 배포 HTML에 반영됩니다.
오류가 발생하면 해당 단계에서 멈추고 확인합니다.

F. Firebase CLI 로그인
firebase projects:list
목록이 표시되고 프로젝트가 있으면 로그인 작업은 생략합니다.
로그인이 필요하면:
firebase login --no-localhost
브라우저에서 받은 인증 코드를 터미널에 입력합니다. Session ID를 넣지 않습니다.
이전의 self-signed certificate 오류가 다시 나오면 Node 22.19.0 이상에서 같은 cmd 창에:
set "NODE_USE_SYSTEM_CA=1"
firebase login --no-localhost
TLS 인증서 검증을 끄는 설정은 사용하지 않습니다.

G. 데이터 접근 규칙 배포
firebase deploy --only firestore --project plant-book-84803
본인 계정만 본인 사진과 기록을 읽고 쓰도록 하는 규칙과 사진 필드 인덱스 제외를 배포합니다.
이 단계가 끝나기 전에는 앱이 기록을 읽거나 저장할 때 permission-denied가 날 수 있습니다.
전달했던 v5 앱의 artifacts/plant-book-84803/users/... 규칙도 호환 목적으로 포함했습니다.
현재 콘솔 규칙을 사용자가 따로 수정했다면 기존 규칙을 백업하고 병합 후 배포해야 합니다.
이 파일을 배포하면 프로젝트의 현재 규칙 파일을 교체하므로, 다른 앱 경로가 있으면 확인하세요.
기존 데이터 자체를 이전하거나 삭제하는 명령은 아닙니다.

H. 컴퓨터에서 확인
npm run preview
브라우저에서 http://127.0.0.1:4173 을 엽니다. HTML 파일 더블클릭 대신 이 주소를 사용합니다.
계정 도감 → 새 계정 만들기 → 이메일/비밀번호 입력 → 사진 선택 → 숲체원/식물 이름 입력
→ 계정에 비공개 저장 → 목록 항목 클릭 → 사진 표시 확인.
GPS는 별도 버튼을 눌렀을 때 요청합니다. 앨범 사진에 현재 GPS를 자동 적용하지 않습니다.
정확한 장소를 모르면 '위치 없이 기록'을 선택합니다. 지도 선택 UI는 다음 단계입니다.
위도·경도를 입력했다면 '입력한 좌표 적용'을 눌러야 기록에 반영됩니다.
시험 종료는 cmd에서 Ctrl+C입니다.

I. Hosting 배포와 다른 기기 시험
firebase deploy --only hosting --project plant-book-84803
출력된 Hosting URL을 컴퓨터와 휴대전화에서 엽니다.
같은 이메일 계정으로 로그인하면 계정 기록이 보입니다.
한 기기에서 수정·삭제 후 다른 기기에서 '계정 기록 새로고침'을 눌러 반영을 확인합니다.
다른 계정으로 로그인하면 다른 계정의 개인 기록은 보이지 않아야 합니다.
기기 도감 기록은 주소/브라우저별로 따로 저장됩니다. 계정 도감과 자동 합쳐지지 않습니다.

J. 기존 기록과 GitHub
'기기 도감 · 기존 기록'에서 이전 IndexedDB 데이터와 v1 JSON 백업을 계속 이용할 수 있습니다.
이미 같은 주소에 기록을 저장했다면 같은 주소에서 새 버전을 열어 확인합니다.
새 주소/기기라면 이전 백업 JSON을 기기 도감 화면에서 복원합니다.
이번 단계는 로컬 기록의 계정 업로드를 자동으로 수행하지 않습니다.
계정 기록 JSON 내보내기·일괄 이전은 아직 미구현입니다. 원본 사진/메모를 별도로 보관하세요.
소스 수정 후 GitHub Desktop에서 커밋·Push origin.
GitHub 업로드는 웹사이트 배포를 자동 실행하지 않습니다(별도 워크플로가 없다면).

K. 자주 만나는 오류
public-config.json 설정 요청: apiKey와 appId를 입력하고 빌드했는지 확인.
auth/operation-not-allowed: 이메일/비밀번호 로그인 사용 설정 확인.
permission-denied: 로그인한 계정과 이 버전의 Firestore 규칙 배포 여부 확인.
resource-exhausted: 콘솔에서 Firestore 사용량 확인. 반복 새로고침을 멈춥니다.
다른 기기 수정 충돌: 최신 목록을 새로 읽은 뒤 다시 수정.
사진 없음: 목록을 새로고침하고 데이터와 사진 문서가 함께 존재하는지 확인.
서버 연결 실패: 입력을 유지한 상태로 다시 시도. 작성 초기화는 내용을 지웁니다.
