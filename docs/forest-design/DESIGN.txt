전국 숲체원 식물 도감 — 데이터 구조·공유 권한 설계 v1
작성일: 2026-10-12
상태: 구현 기준 설계. 원격 서버 연결·권한 규칙·앱 화면은 아직 미구현.

1. 목적과 범위
필수 A: 전국 숲체원별로 위치가 있는 식물 관찰 정보를 저장하고 공유한다.
필수 B: 사진 촬영 또는 기존 사진 업로드로 개인 식물 도감을 완성한다.
시범 운영은 1~2개 숲체원으로 시작하되 기관을 추가해도 같은 데이터 구조를 사용한다.
이름만 바꾸어 전국 자료를 보유한 것처럼 표시하지 않는다.
현재 코드의 JPEG 변환, 사진·GPS 비동기 처리, 오류 안내, 접근성, 백업을 활용한다.
현재 IndexedDB는 개인 로컬 기록용으로 유지하며 공유 서버인 것처럼 사용하지 않는다.

2. 사용 흐름
사진 촬영/선택 → 숲체원 선택 → 관찰 장소 확인 → 이름 입력/AI 후보 선택
→ 비공개 저장 → 선택적으로 공유 신청 → 담당자 검토 → 기관별 공유 목록에서 조회.
로그인 전 임시 기록은 기기에만 저장하고, 공용 저장은 사용자 구분 후 제공한다.
여러 사람이 같은 브라우저를 쓰는 상황을 고려해 기기 기록과 계정 기록을 구분한다.
계정 전환 시 이전 사용자의 사진·리스트·검토 권한·비동기 응답을 초기화한다.

3. 데이터 구성
profiles: 사용자 ID, 비공개 계정 설정, 표시용 별칭. 이메일 등은 공개 기록에서 제외.
centers: 기관 ID, 기관명, 시도·주소, 공개 지도 중심점, 교육용 식물 목록, 출처·확인일.
species: 안정된 식물 ID, 국명·학명, 특징, 설명 출처, 자료 이용 조건, 검토 상태.
observations: 소유자 ID, 기관 ID, 식물 ID 또는 미확인 이름, 메모, 사진 ID,
  관찰 시각, 관찰 좌표와 좌표 입력 방식, 서버 생성·수정 시각, 버전, 공개 진행 상태.
media: 사진 ID, 소유자, 관찰 ID, 비공개 객체 경로, JPEG 크기·용량, 처리 상태.
shareSubmissions: 사용자가 제출한 공유용 사본. 제출 버전과 기관을 고정한다.
publicObservations: 서버가 작성하는 공개용 사본. 원본 observations와 별도 저장.
reviews: 제출 ID, 담당자 ID, 판단·정정 이유·검토 시각. 작성 후 변경하지 않는 이력.
reviewerGrants: 서버 관리자가 부여하는 사용자-기관별 담당 권한. 클라이언트 수정 금지.

관계: 사용자 한 명은 여러 관찰을 가진다. 관찰 하나는 기관 하나에 속한다.
식물 항목 하나에는 여러 관찰이 연결된다. 이름을 모르면 speciesId=null로 저장한다.
이름 문자열이 같다고 자동으로 같은 종으로 합치지 않는다. 동명이명·오동정을 고려한다.
관찰은 시범 버전에서 사진 한 장을 갖는다. 한 종의 관찰은 여러 번 남길 수 있다.
기본 식물 설명(species)과 개인 메모(observations)는 서로 다른 데이터이다.

4. 위치 원칙
centerId는 원격 관찰 저장 전에 실제 활성 기관 목록에서 선택한다.
GPS 좌표가 있다고 해당 숲체원에 실제 방문했다고 인증하지 않는다.
기관 자동 제안은 사용자가 확인해야 하며 목록에서 수동 변경할 수 있다.
촬영: 사용자가 허용할 때 현재 GPS를 관찰 지점 후보로 사용한다.
앨범: 현재 GPS를 과거 촬영 위치로 자동 적용하지 않는다. 지도 지정/기관만 선택 가능.
locationSource는 gps, map, center_only, legacy_unspecified로 구분한다.
정확한 좌표가 없으면 null로 저장한다. 기관 중심점을 실제 촬영 좌표로 복사하지 않는다.
observedAt는 실제 관찰 시각이며 모르면 null. uploadedAt과 구분한다.
좌표 범위(위도 -90~90, 경도 -180~180), 숫자 유한성, 날짜 형식을 서버에서도 검증한다.
공개 기본 위치는 숲체원 중심점이며 화면에 '기관 위치 · 관찰 지점 아님'을 표시한다.
공개 관찰 지점은 사용자 별도 동의와 담당자 검토를 모두 통과한 경우만 허용한다.
보호 필요 기록은 기관 단위 위치만 공개하거나 공유를 거절할 수 있다.
공개 댓글·메모에 개인 연락처나 좌표가 다시 포함되지 않는지도 검토한다.

5. 공유 정책과 권한
기본 비공개. 저장 버튼과 공유 신청 버튼을 구분하며 미리 체크된 공개 동의를 두지 않는다.
미로그인: 활성 기관·공개 도감 자료·승인된 공개 기록 조회만 가능.
기록 소유자: 본인 원본 조회/수정/삭제, 본인 사진 조회, 공유 신청/철회 가능.
기관 담당자: 권한이 있는 기관에 제출된 공유 사본만 조회하고 승인/반려/정정 제안 가능.
담당자는 공유하지 않은 개인 관찰과 정밀 좌표를 일괄 열람하지 못한다.
관리자: 기관·담당 권한·공공 도감 자료 관리. 개인 원본 접근은 기본적으로 금지한다.
사진 저장소는 비공개이며 공개 사진도 활성 공개 기록의 권한 검사를 통해 제공한다.
클라이언트가 ownerId, reviewerGrants, 검토 결과, 공개 사본을 임의로 쓸 수 없어야 한다.
서버는 로그인 토큰으로 ownerId를 결정한다. 화면에서 숨기는 것만으로 보호하지 않는다.
목록, 단건 조회, 이미지 요청, 수정, 삭제를 각각 서버에서 검사한다.

6. 공개 상태와 변경
private: 개인 기록만 존재.
pending: 공유 제출 완료. 일반 방문객에게 미공개.
published: 해당 원본 버전의 공유 사본을 승인하여 공개.
rejected: 반려 이유를 본인에게 안내. 수정 후 다시 신청 가능.
withdrawn: 철회/수정/삭제로 공개 접근을 종료.
제출은 immutable snapshot이며 originalRevision을 갖는다.
담당자의 승인 처리와 원본 버전 확인은 하나의 원자적 서버 작업으로 수행한다.
원본이 변경된 오래된 제출은 승인할 수 없다. 서버가 기준 버전 불일치를 반환한다.
공개 기록의 이름·사진·메모·기관·위치를 바꾸면 기존 공개를 철회하고 재검토한다.
개인 이름 선택과 담당자 정정 제안은 구분한다. 원본 수정은 소유자의 동의를 받는다.
공개 철회는 서버 읽기와 이미지 접근부터 차단한다. 객체 정리 실패는 재시도한다.
공개 사진은 영구 공개 URL로 저장하지 않는다. 인증 없는 버킷 공개 금지.
시범 버전은 공개 응답/사진 no-store 정책과 접근 검사로 철회 후 새 조회를 차단한다.
이미 타인이 다운로드하거나 캡처한 사본까지 회수할 수 있다고 안내하지 않는다.

7. 검토와 AI 결과
AI: 공급자·모델/버전·실행 시각·후보·공급자가 실제 반환한 점수를 별도로 저장한다.
점수가 없으면 null. 점수를 정확도나 확정 확률로 바꾸어 표현하지 않는다.
identification.status는 unknown, user_selected, staff_reviewed를 구분한다.
담당자 검토 표시에는 검토 기준/범위를 기록한다. 전문가 확정이라고 과장하지 않는다.
사진의 후보 확인과 도감 설명 출처 검증은 별도 작업이다.
AI 응답 실패/낮은 식별 품질이면 수동 입력·이름 모름 저장을 계속 허용한다.
AI 호출은 서버 식별 어댑터를 통해 수행한다. 브라우저·GitHub에 비밀 키를 넣지 않는다.
후보 응답은 같은 사진/요청 ID에만 반영한다. 새 사진 선택·계정 전환 후 응답은 무시한다.
실제 AI 연결 전에는 '준비 중' 표시. 예시 후보는 시연용이라고 명시한다.
species 설명은 공개자료/이용 허용 자료를 기반으로 출처를 표시한다.
AI가 설명을 요약해도 출처에 없는 내용을 확정 정보처럼 덧붙이지 않는다.

8. 사진 저장과 실패 처리
기존 긴 변 1,000px JPEG 변환을 활용한다. 클라이언트 한도는 서버에서도 검증한다.
사진을 처리하여 EXIF 등을 제거한 사본을 사용하고 사용자의 원본 파일은 수정하지 않는다.
변환된 JPEG에 메타데이터가 남지 않는지 구현 시 검증한다.
객체 경로는 서버가 결정하며 사용자 입력 URL/다른 소유자 경로를 수용하지 않는다.
초안 ID 발급 → 개인 사진 업로드 → 저장소 검증 → 관찰 확정 순서.
사진은 DB 문서의 Base64 필드가 아니라 객체 저장소에 저장하고 DB에는 mediaId만 넣는다.
DB와 사진 저장소가 별개이면 하나의 원자적 트랜잭션이라고 가정하지 않는다.
실패 초안/고아 사진은 비공개 유지 후 정리 작업이 재시도한다.
저장 성공 후 동일 요청 재시도는 같은 관찰을 반환한다. 중복 생성하지 않는다.
수정은 revision 비교로 충돌을 감지하고 다른 기기 변경을 덮어쓰지 않는다.
용량 한도/요청 제한/사용량 안내는 선택한 제공자 조건 확인 후 구현한다.

9. 내 도감 계산
관찰 수: 삭제되지 않은 본인의 확정 저장 기록 수.
식물 종류 수: speciesId가 있는 본인 관찰의 고유 ID 수. 미확인 기록은 별도 집계.
교육 도감 달성률: 기관의 targetSpeciesIds와 본인 관찰 speciesId 교집합 / 목표 목록 수.
목표 목록이 없으면 달성률을 표시하지 않는다. 전국 모든 종을 분모로 삼지 않는다.
후보 선택 기록과 담당자 검토 기록의 집계를 구분하여 보여준다.
기관별 목록은 공개 기록만 검색하며 숨김/삭제된 기록은 결과와 집계에서 제외한다.
리스트는 페이지 단위로 조회한다. 위치 탐색은 기관 필터부터 구현한다.

10. 기존 기록 이동
현재 local-store.js의 필드: id,name,description,createdAt,updatedAt,image,location.
createdAt은 기록 생성 시각이므로 실제 관찰 시각으로 단정하지 않는다.
로그인 후 사용자가 로컬 기록을 미리 보고 기관을 지정하며 서버 이전을 선택한다.
자동 업로드/자동 공개하지 않는다. 기존 사진·메모·좌표·기록 생성 시각을 보존한다.
종 ID는 null로 시작한다. 이름 문자열만으로 확정 종을 지정하지 않는다.
좌표 출처는 legacy_unspecified, 실제 관찰 시각은 사용자 확인 전 null.
ownerId는 현재 인증 사용자. 로컬 기록에 다른 계정의 ownerId를 새로 써넣지 않는다.
기록별 이전 요청은 사용자+로컬 ID+명시한 이전 작업 ID로 중복 방지한다.
사진 검증·업로드·원격 저장을 모두 확인한 후에만 이전 완료 표시.
기존 IndexedDB와 JSON 백업은 남긴다. 자동 삭제하지 않는다.
일부 실패 시 성공/실패를 기록별로 안내하고 실패 항목만 재시도한다.
기존 백업 형식 bangjangsan-local-backup v1의 의미를 바꾸지 않는다.
새 서버 자료의 백업은 별도의 version 2 형식으로 정의한 다음 제공한다.

11. 코드 연결
src/photo-flow.js, dialog.jsx, styles.css: 기존 흐름·접근성 활용.
src/local-store.js: 기존 개인 기기 기록과 v1 백업 유지.
신규 데이터 저장 어댑터: contracts.ts의 ObservationRepository 구현.
신규 사용자 어댑터: 계정 상태 변경과 인증 토큰 처리.
신규 기관/도감 화면: 기관 선택, 공유 목록, 종별 묶음, 담당자 제출 검토.
기존 Spark 앱의 단독 CSP/connect 설정은 원격 연결 주소 확정 시 제한적으로 변경.
어댑터 경계를 먼저 두어 저장소와 AI 제공자를 화면 코드와 분리한다.
UI 검증은 편의 기능이며 최종 권한·필드 검증은 서버에서 강제한다.

12. 구현 전에 남아 있는 설정
사진 저장소와 AI 서버 제공자, 인증 방식, 무료 한도·초과 처리, 데이터 저장 지역 확인.
실제 기관 목록·좌표·담당자와 식물 출처·이용 조건 확보.
Spark 유지 선호를 반영하되 브라우저 기기 저장만으로 공유를 구현했다고 주장하지 않는다.
현재 Firebase 요금제·서버 설정·GitHub 저장소는 변경하지 않았다.
현재 v6 HTML과 소스는 수정하지 않았다. 이 문서는 다음 개발의 기준이다.
이 단계에는 실제 사진 전송, 계정 생성, 공개 배포가 없다.

13. 해커톤 연결
기본 시연: 사용자 A 저장 → 공유 신청 → 기관 담당자 승인 → 다른 기기 사용자 B 조회.
추가 시연: 기존 앨범 사진의 위치 수동 지정 → AI 후보 확인 → 종별 개인 도감 누적.
모든 예시 기관·좌표·후보는 실제 검증 자료와 구분한다.
사용량, 식별 결과, 업무시간 감소 등은 실제 측정 후 기록하고 수치를 만들어내지 않는다.
