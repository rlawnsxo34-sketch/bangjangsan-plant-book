저장한 사진 추가·바꾸기 — v24

이용 순서
내 도감 → 바꿀 기록 열기 → 사진 추가·바꾸기.
최신 사진을 불러온 뒤 앨범에서 여러 장 또는 카메라로 한 장씩 추가할 수 있습니다.
사진 빼기와 대표사진으로 버튼으로 순서·구성을 바꿉니다. 총 1~3장을 남길 수 있습니다.
3장이 꽉 찬 상태에서 다른 사진을 넣으려면 기존 사진을 먼저 빼세요.
사진을 모두 뺀 상태에서는 저장할 수 없습니다. 새 사진을 한 장 이상 추가하세요.
사진 변경 저장하기를 눌러야 계정 도감에 반영됩니다. 고르거나 빼는 즉시 원본 기록을 바꾸지는 않습니다.
저장하지 않고 닫으면 변경을 버릴지 묻습니다. 브라우저가 허용하면 새로고침/종료 때도 경고하지만, 휴대폰 강제 종료까지 막을 수는 없습니다.
새 사진 준비가 지연되면 사진 추가 취소를 누를 수 있습니다.

AI 선택 정보
최종 대표사진이 원래 대표사진과 달라질 때만 이전 AI 선택 정보를 지웁니다.
추가사진만 더하거나 빼면 기존 대표사진의 AI 정보는 유지합니다.
대표사진을 바꿔도 식물 이름과 글을 자동으로 고치지는 않습니다. 새 사진과 이름이 맞는지 직접 확인하세요.
이 화면에서는 AI를 자동 재호출하지 않습니다.

공유
성공적으로 사진 변경을 저장하면 해당 기록의 공유 신청·기존 공개를 함께 철회합니다.
대표사진이 같고 추가사진만 바꾸는 경우에도 다시 검토받도록 철회합니다.
다시 공유하려면 함께 보기에서 신청하세요. 담당자가 확인하기 전에는 다시 공개되지 않습니다.
공유할 사진은 함께 보기에서 직접 고릅니다. 고르지 않은 사진은 본인만 볼 수 있습니다.
취소하거나 저장에 실패했다는 이유만으로 사진 또는 공개를 일부만 변경하지 않습니다. 서버에는 한 번에 반영합니다.
응답을 못 받았지만 실제 저장되었을 가능성이 있는 경우에는 이미 사진 변경과 공개 철회가 반영되었을 수 있습니다. 같은 변경 다시 저장 또는 최신 기록 다시 불러오기로 확인하세요.
이미 다른 사람이 내려받은 사진이나 캡처까지 지우지는 않습니다.

저장 오류·기기 간 충돌
다른 기기에서 먼저 글이나 사진을 바꾸면 오래된 화면으로 덮어쓰지 않습니다.
변경한 사진은 화면에 유지하고 안내를 표시합니다. 최신 기록 다시 불러오기는 변경을 버릴지 확인한 뒤 서버의 사진을 가져옵니다.
저장 결과가 불확실하면 같은 변경 다시 저장을 누르세요. 처음과 같은 요청 ID와 사진으로 확인해 중복 수정·불필요한 공개 철회를 줄입니다.
저장 요청 후에는 추가 변경을 잠급니다. 다시 편집하려면 최신 기록을 불러와 상태를 확인하세요.
수정 화면의 미저장 사진은 기기의 7일 임시 보관 대상이 아닙니다. 화면을 닫기 전에 저장하고, 원본 사진은 따로 보관하세요.
계정/기관 전환이나 닫기 이후 도착한 사진 준비·조회·저장 응답을 이전 화면에 표시하지 않습니다.
기존 한 장짜리 기록을 자동 변환하거나 일괄 삭제하지 않습니다.

구조와 제한
Spark 개발 구조, 한 기록 최대 3장, 사진당 압축 JPEG 120,000바이트 제한을 유지합니다.
사진 추가는 새 관찰 기록을 만들지 않고 해당 기록을 수정합니다.
사진 문서에 내부 저장 요청 ID(lastEditId)를 추가하고, 기록 revision과 사진·공개 철회를 하나의 거래로 처리합니다.
사진만 따로 수정하는 요청, 넘치는 사진, 잘못된 요청 ID, 대표사진 변경 후 옛 AI 정보 유지 등은 규칙으로 막습니다.
Firestore 규칙 변경이 필요합니다. Cloudflare Worker·Pl@ntNet 키·요금제는 바꾸지 않습니다.

배포 후 확인
1. 기존 한 장짜리 기록에 사진을 추가하고 다른 기기에서도 확인하세요.
2. 대표사진을 바꿨을 때 AI 선택 정보가 없어지고 이름·글은 유지되는지 확인하세요.
3. 추가사진만 수정했을 때 AI 정보가 유지되는지 확인하세요.
4. 저장하지 않고 닫기를 취소하면 수정 화면과 사진이 남는지 확인하세요.
5. 사진을 모두 빼면 저장 버튼이 비활성화되는지 확인하세요.
6. 이미 공유한 기록을 수정하면 공개에서 빠지고 다시 신청할 수 있는지 확인하세요.
7. 두 기기에서 같은 기록을 수정하면 오래된 내용이 덮어쓰이지 않는지 확인하세요.
실제 휴대폰 촬영·레이아웃·통신 장애·배포·방문객 시험은 별도로 확인해야 합니다.
