ㅇㄱㅁㅇ v19 — 가로형 로고 배치와 시작 안내 개선

현재 적용 절차는 이 안내문을 먼저 읽어주세요.
방문객 사용 시험을 자동으로 시작하거나 응답을 수집하는 기능은 추가하지 않았습니다.

1. 가로형 로고
- 제공한 ‘ㅇㄱㅁㅇ_가로형.png’를 모든 화면의 상단에 배치했습니다.
- 원본 그림·색·투명 배경·가로세로 비율을 바꾸지 않고 사용합니다.
- 원본 파일 크기는 2048×1143이며, 화면에서는 작게 표시합니다.
- 배포에 사용하는 파일은 public/brand/egmy-horizontal-v19.png입니다.
- 원본을 다시 그리거나 일부를 잘라내지 않았습니다.
- 로고를 불러오지 못하면 ‘ㅇㄱㅁㅇ · 이건뭐야’ 글자로 이름을 보여줍니다.
- 홈 화면 아이콘·앱 썸네일은 기존 정사각형 이미지를 유지합니다.
- 아래쪽의 국립장성숲체원 기관 로고와 개발·시범 적용 표시는 유지합니다.
- 좁은 휴대폰 화면에서는 상단의 장식 문구를 숨겨 공간을 확보합니다.

2. 다음 단계로 추가한 시작 안내
숲체원 선택 화면:
- 이 서비스에서 무엇을 할 수 있는지 두 가지로 간단히 안내합니다.
- 설명 읽기와 한 줄 남기기는 로그인 없이 이용합니다.
- 사진으로 찾기는 로그인과 사진 전송 동의 후 이용합니다.
- 상단 로고에 캐릭터가 함께 있으므로 기존의 큰 캐릭터 그림을 중복해서 표시하지 않았습니다.

숲 둘러보기 화면:
- ‘어떻게 시작할까요?’에서 ‘나무 설명부터 보기’와 ‘사진으로 알아보기’를 고릅니다.
- 나무 설명부터 보기를 누르면 세 나무 설명 시작 부분으로 이동합니다.
- 사진으로 알아보기에는 로그인이 필요하다는 안내를 붙였습니다.
- 이미 적어둔 글이 있으면 로그인 전에 기록 파일을 먼저 받으라는 안내를 표시합니다.
- 이동 버튼을 누르는 것만으로 방문객 메모를 삭제하거나 사진을 외부로 보내지 않습니다.
- 로그인/로그아웃 시 방문객 메모가 지워지는 기존 정책은 유지합니다.
- ‘처음이라면 여기를 읽어보세요’를 펼치면 시작 방법·이름을 모를 때·보관 방법을 읽을 수 있습니다.
- 작은 화면에서는 시작 버튼을 위아래로 배치하고, 그보다 큰 화면에서는 나란히 배치합니다.

3. 유지한 내용
- 기존 QR 주소와 center/view 값
- 기존 식물 설명·사진·관찰 장소·담당자 확인 정보가 담긴 src/experience-data.js
- 로그인·사진 식별·내 도감·함께 보기·이 기기 기록
- 사진 기록의 v16 임시 보관과 복구 정책
- Firebase 프로젝트, Spark 요금제, Firestore 규칙·인덱스, Cloudflare Worker·API 키
- 방문객 글의 화면 내 임시 유지와 기록 파일 받기 방식

4. 기존 자료를 지키면서 적용하기
(1) 기존 bangjangsan-plant-book 폴더 전체를 다른 폴더로 복사해 백업합니다.
(2) 이번 ZIP을 별도 폴더에 압축 해제합니다.
(3) 새 파일을 기존 프로젝트에 복사하되 아래 항목은 자신의 기존 것을 유지합니다.
    public-config.json
    src/experience-data.js
    직접 추가한 사진(public/experience 등)
    .git 폴더
(4) 새 src/BrandLogo.jsx와 public/brand/egmy-horizontal-v19.png는 반드시 함께 복사합니다.
    새 로고 파일은 그대로 사용하고, 기존 사진 폴더를 지우지 마세요.
    node_modules와 backend/node_modules는 복사하지 않습니다.
(5) 프로젝트 폴더의 명령 프롬프트(cmd)에서 실행합니다.
    cd /d "C:\Users\김준태\Documents\GitHub\bangjangsan-plant-book"
    npm ci
    npm test
    npm run build
    firebase deploy --only hosting --project plant-book-84803
(6) 기존 QR 주소를 열어 새로고침합니다. 이전 화면이 보이면 창을 닫았다 다시 열어보세요.
    브라우저 데이터 삭제는 기존 기기 기록까지 지울 수 있으므로 업데이트 방법으로 사용하지 마세요.
(7) GitHub Desktop에서 변경 사항을 확인한 뒤 Commit → Push origin 합니다.

기존 v18 설정이 정상 동작했다면 Firebase·Cloudflare를 다시 설정하지 않습니다.
Firebase init도 실행하지 않습니다. 이번에는 Hosting만 배포합니다.
회사 PC에서 인증서 설정이 필요했다면 같은 cmd 창에서 먼저 실행합니다.
    set "NODE_USE_SYSTEM_CA=1"

가로형 로고는 별도 이미지 파일입니다.
code_artifact.html만 복사하는 방식으로는 로고가 표시되지 않을 수 있습니다.
위 npm run build와 Firebase Hosting 배포로 dist 폴더 전체를 배포해주세요.

5. 배포 후 먼저 확인할 것
- 휴대폰 상단에 가로형 로고가 잘리지 않고 보이는지.
- 기존 정사각형 홈 화면 아이콘과 아래쪽 기관 로고가 유지되는지.
- 기관 선택 화면에서 무엇을 하는 서비스인지 이해할 수 있는지.
- 기존 QR로 숲 둘러보기 화면이 열리는지.
- 나무 설명부터 보기 버튼이 설명 시작 부분으로 이동하는지.
- 사진으로 알아보기에 로그인 안내가 보이고, 버튼을 눌러도 곧바로 사진을 전송하지 않는지.
- 글을 적었을 때 기록 파일을 먼저 받으라는 안내가 나타나는지.
- 기존 관찰 장소·사진·설명이 유지되는지.

방문객 시험은 이 화면을 검토하고 필요한 수정을 마친 뒤 진행하시면 됩니다.
