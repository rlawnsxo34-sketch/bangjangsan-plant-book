v32 적용 안내 — 나무 지도와 담당자 지도 위치 등록

이번 버전은 새 Firestore 규칙과 카카오 지도 설정이 필요합니다.
처음부터 따라 하는 방법: TREE_MAP_SETUP.txt

1. 기존 프로젝트 전체를 백업합니다.
2. ZIP을 새 폴더에 풀고 본인 설정·현장 자료를 아래 상세 안내대로 보존합니다.
3. public-config.json의 기존 Firebase·Pl@ntNet 설정을 유지하고 kakaoMap.javascriptKey를 추가합니다.
4. 카카오 개발자 사이트에서 지도 사용 설정과 JavaScript SDK 도메인을 등록합니다.
5. 프로젝트 루트에서 실행합니다.
   npm ci
   npm test
   npm run build
6. 규칙부터 배포합니다.
   firebase deploy --only firestore --project plant-book-84803
7. 화면을 배포합니다.
   firebase deploy --only hosting --project plant-book-84803
8. 기존 담당자 계정으로 로그인 → 숲 둘러보기 → 나무 지도에서 위치를 고르고 공개합니다.
9. 로그인하지 않은 다른 기기에서 같은 기관의 나무 표시와 사진을 확인합니다.

본인 public-config.json, backend/wrangler.jsonc, .firebaserc(있을 때), .git,
src/experience-data.js, src/observation-places.js의 기관 ID·장소 설정과 추가 자료를 보존하세요.
Firebase init과 Worker 재배포는 하지 않습니다. 브라우저 저장 데이터도 지우지 마세요.
지도 등록은 기존 기관 담당자 권한을 사용합니다.
실제 위치는 임의 등록하지 않았습니다. 지도에서 확인해 공개해야 나무 표시가 나옵니다.
변경 파일: docs/CHANGED_FILES.txt
검증: verification/current-checks.txt

아래는 새 폴더로 옮길 때의 상세 안내입니다.

정리본 적용 순서 — 이미 배포 중인 프로젝트 기준

1. 전체 백업
기존 bangjangsan-plant-book 폴더를 다른 위치에 복사해 보관하세요. 작업 중인 파일을 먼저 저장하세요.
기존 파일을 바로 전부 삭제하지 마세요.

2. 새 폴더 준비
이 ZIP을 별도의 새 폴더에 압축 해제하세요. 기존 폴더 위에 덮어쓰면 옛 파일이 남으므로 정리 효과가 없습니다.
새 폴더 안에 package.json, src, public이 바로 보이는지 확인하세요.

3. 본인 자료 옮기기
백업에서 아래 자료를 새 폴더에 복사하세요.
- public-config.json: 본인 Firebase·서버 연결 설정
- src/experience-data.js: v24에서 사용하던 본인 현장 자료를 유지합니다. 더 오래된 버전의 굴참나무 사진·장소는 갈참나무에 재사용하지 마세요.
- 직접 추가한 사진 및 기타 수정한 소스: 변경 내용을 비교해 옮기세요. public 폴더 전체를 덮어쓰면 새 로고가 예전 것으로 바뀔 수 있습니다.
- backend/wrangler.jsonc: 본인 서버 설정을 수정했다면 유지
- .firebaserc: 기존 파일이 있을 때만 복사
- .git 폴더: 같은 GitHub 저장소와 이력을 이어가려면 복사 (Windows 숨김 항목 표시 필요)
- .dev.vars 등 개인 환경설정: 필요할 때만 본인 PC에서 옮기고 GitHub에는 올리지 마세요.
Firestore 규칙·인덱스·빌드 파일을 직접 수정한 경우에도 먼저 차이를 비교하세요.
node_modules, dist, .firebase, backend/.wrangler와 예전 압축파일은 옮기지 않습니다.
브라우저 내부 기기 기록은 파일 복사로 이동하지 않습니다. 필요한 기록은 앱에서 별도 백업하세요.

4. 설치와 확인
새 폴더에서 터미널을 열고 차례대로 실행하세요.
npm ci
npm test
npm run build

회사 PC에서 이전에 인증서 설정이 필요했다면 같은 명령 프롬프트에서 먼저 실행합니다.
set "NODE_USE_SYSTEM_CA=1"

5. 화면 배포
firebase deploy --only hosting --project plant-book-84803
Firebase init은 다시 실행하지 않습니다. v32에서는 위 순서대로 새 Firestore 규칙을 먼저 배포해야 합니다. Worker는 재배포하지 않습니다.
Hosting은 dist를 사용하므로 빌드가 끝난 뒤 배포하세요.
기존 QR 주소로 앱을 열어 로고·사진 검색·내 도감·기록 카드를 확인하세요. 브라우저 데이터는 지우지 마세요.

6. GitHub 연결
새 폴더에 기존 .git을 옮겼다면 GitHub Desktop에서 기존 항목 대신 새 폴더를 Add local repository로 선택하세요.
Changes에서 이번 변경과 CLEANUP.txt의 정리 목록을 확인한 후 Commit → Push origin을 진행하세요.
이전에 dist가 이미 Git에 등록되어 있다면 git rm -r --cached --ignore-unmatch dist 명령으로 추적만 해제할 수 있습니다. 실제 dist 파일은 남습니다.
변경 목록에 비밀키·.dev.vars·백업 JSON·node_modules가 포함되어 있으면 올리지 마세요.
문제가 없음을 확인할 때까지 이전 백업은 보관하세요.

이번 ZIP은 프로젝트 파일 정리본이며, 사용자 PC나 GitHub 파일을 직접 삭제한 상태는 아닙니다.
