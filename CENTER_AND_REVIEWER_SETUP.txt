현재 v24에서는 사진을 직접 선택하고 미리보기를 확인한 뒤 신청합니다. 여러 사진 검토·공개 방법은 docs/SHARE_PHOTOS.txt를 먼저 읽으세요. 아래 기관 등록/담당자 권한 설정은 기존 절차입니다. 이미 설정했다면 다시 만들 필요 없습니다.

숲체원 등록·담당자 지정·공유 시연 안내 — v8
작성일: 2026-10-12

이번에 새로 해야 하는 작업
기존 Firebase 프로젝트를 그대로 사용합니다.
새 프로젝트, Storage, Cloud Functions, Pl@ntNet 키는 이번 단계에 필요하지 않습니다.
새 규칙/인덱스 배포 → 기관 등록 → 담당자 권한 지정 → 새 웹사이트 배포 순서입니다.
이 안내는 콘솔에서 사용자가 직접 설정하는 절차입니다. 실제 프로젝트 설정은 변경하지 않았습니다.

1. 파일 적용과 기존 설정 보존
기존 프로젝트와 기기 도감 JSON을 백업합니다.
새 ZIP 내용물을 기존 bangjangsan-plant-book 폴더에 적용합니다.
기존 .git 폴더와 이미 입력한 public-config.json은 유지하세요.
ZIP의 public-config.json에는 비밀 값이 없으며 apiKey/appId가 비어 있습니다.
덮어썼다면 기존 백업 또는 Firebase 콘솔의 웹 앱 구성에서 값을 다시 입력합니다.
emulators.enabled는 실제 배포 시 false여야 합니다.

2. 코드 설치·빌드와 규칙 배포
cmd에서:
cd /d "C:\Users\김준태\Documents\GitHub\bangjangsan-plant-book"
npm ci
npm test
npm run build
firebase projects:list
firebase deploy --only firestore --project plant-book-84803

프로젝트 ID가 다르면 본인 프로젝트 ID로 바꿉니다.
기존 콘솔 규칙을 별도 수정했다면 백업하고 병합해 배포해야 합니다.
firebase init은 실행하지 않습니다. 설정 파일이 이미 포함되어 있습니다.
이번 인덱스는 공유 신청자 조회, 기관별 검토 대기 목록, 공개 목록 정렬에 필요합니다.
Firestore Database → 색인/Indexes에서 생성 완료를 확인합니다. 생성 중에는 몇 분 기다립니다.
permission-denied가 나면 공개 테스트 규칙으로 바꾸지 말고 로그인/권한/배포 파일을 확인합니다.

3. 숲체원 등록
Firebase 콘솔 → 기존 프로젝트 → Firestore Database → 데이터(Data).
컬렉션 시작(Start collection)을 누르고 컬렉션 ID를 정확히 입력합니다:
forestCenters

문서 ID는 기관을 구분하는 고정 ID입니다. 예: jangseong
자동 ID 대신 직접 입력하면 담당자 설정 시 같은 ID를 사용하기 쉽습니다.
아래 필드를 추가합니다(예시는 실제 사용 전 기관명을 확인하세요).

필드명       유형       값/설명
name         string     국립장성숲체원 등 실제 사용할 기관명
active       boolean    true
mapCenter    null       기관 지도 중심점을 아직 확인하지 않았다면 null
isDemo       boolean    실제 기관이면 false, 허구의 시연 기관이면 true

null은 문자열 "null"이 아니라 null 유형입니다.
active도 문자열 "true"가 아니라 boolean 유형입니다.
정확한 기관 중심점이 확인되면 mapCenter를 map 유형으로 만들고 하위 lat/lng를 number로 등록합니다.
방문자의 개인 GPS나 보호 대상 식물의 위치를 기관 중심점으로 입력하지 않습니다.
좌표를 넣지 않아도 기관 이름으로 공유할 수 있습니다. 0,0을 임의 좌표로 넣지 않습니다.
기관 문서는 활성 상태일 때 로그인 없이 읽을 수 있으므로 공개 가능한 내용만 입력합니다.
기관별로 같은 절차를 반복하면 여러 숲체원이 목록에 나타납니다.
앱이 전국 기관을 자동 등록하거나 방문 사실을 인증하는 것은 아닙니다.

4. 담당자 계정 만들기
앱의 계정 도감 → 새 계정 만들기로 담당자의 이메일 계정을 먼저 생성합니다.
사용자/담당자를 구분해 시험하려면 작성자용 계정과 담당자용 계정 두 개를 사용하세요.
Firebase 콘솔 → Authentication → 사용자(Users)에서 담당자 계정을 찾습니다.
해당 사용자의 UID를 복사합니다. 이메일 주소나 CLI Google 계정 이름을 사용하는 것이 아닙니다.

5. 담당자에게 기관 권한 부여
Firestore 데이터에서 다음 구조를 만듭니다:
forestReviewerGrants / 담당자_UID / centers / 기관_ID

순서:
① 컬렉션 forestReviewerGrants를 시작합니다.
② 문서 ID에 복사한 담당자 UID를 정확히 붙여 넣습니다.
   상위 문서가 비어 있는 상태를 콘솔에서 만들기 어렵다면 label(string)에 '담당자'를 넣어도 됩니다.
   label은 앱 권한에 사용하지 않습니다. 이메일 등 개인정보를 넣을 필요가 없습니다.
③ 그 문서 안에서 하위 컬렉션 centers를 시작합니다.
④ 하위 문서 ID에 3번에서 등록한 기관 ID(예: jangseong)를 입력합니다.
⑤ active 필드를 boolean 유형 true로 저장합니다.

예:
forestReviewerGrants
  담당자_UID
    centers
      jangseong
        active: true

사용자가 앱에서 자신의 담당자 권한을 만들 수는 없습니다.
Firebase 콘솔의 프로젝트 관리자만 이 설정을 합니다.
여러 기관을 담당하면 centers 안에 각 기관 ID 문서를 추가합니다.
권한을 회수하려면 해당 하위 문서의 active를 false로 변경하거나 문서를 삭제합니다.
변경 후 앱의 공유 목록 새로고침을 누릅니다. 실제 승인 권한은 매번 서버 규칙에서 검사합니다.

6. Hosting 배포
firebase deploy --only hosting --project plant-book-84803
출력된 Hosting URL을 엽니다. 이미 접속 중이었다면 새로고침합니다.
규칙만 바꾸고 v7 화면을 그대로 쓰면 공유 기능을 사용할 수 없습니다.

7. 작성자 화면에서 공유 신청
작성자 계정으로 로그인 → 계정 도감에서 사진·이름·기관·메모를 비공개 저장.
공유 도감 · 검토 → 공유 숲체원 선택 → 공유할 개인 기록 선택.
공개 메모에 다른 사람과 나눌 내용만 입력합니다. 개인 메모는 자동 복사하지 않습니다.
사진에 얼굴/연락처/민감한 장소가 들어 있는지 확인합니다.
공개 항목과 선택한 기관을 확인하고 동의 체크박스를 직접 선택합니다.
담당자 검토를 위한 공유 신청을 누릅니다.
내 공유 신청 상태가 검토 대기인지 확인합니다.
기존 개인 기록의 기관명이 직접 입력값이더라도 공유 기관은 위에서 선택한 공식 등록 기관입니다.
방문/관찰 기관을 정확하게 선택할 책임은 신청자에게 있으며 담당자가 검토합니다.
대기 중 내용을 바꾸려면 기존 신청을 철회한 뒤 다시 신청합니다.

8. 담당자 화면에서 승인/반려
다른 브라우저/기기에서 담당자 계정으로 로그인합니다.
공유 도감 · 검토 → 지정받은 공유 숲체원 선택 → 공유 목록 새로고침.
기관 담당자 검토 영역에 대기 기록이 나타납니다.
검토하기 → 사진·공개 메모 확인 → 공유 승인 또는 공유 반려 선택.
검토 사유를 입력하고 검토 결과 저장을 누릅니다.
담당자는 신청한 공유 사본만 봅니다. 개인 메모/정확한 GPS/공유하지 않은 원본은 보지 못합니다.
승인은 공개 적합성 검토입니다. 전문가 동정이나 AI 식별 결과 확정을 의미하지 않습니다.
같은 기관 대기 목록은 최신 10개를 보여주며 처리 후 새로고침하면 다음 기록이 나타납니다.

9. 방문자 공개 화면 확인
로그아웃한 브라우저/다른 기기에서 공유 도감 · 검토를 엽니다.
기관 선택 → 공유 목록 새로고침 → 승인된 기록 클릭 → 사진과 공개 메모 확인.
공개 위치는 기관 중심점입니다. 실제 관찰 좌표로 표시하지 않습니다.
기관 좌표가 없으면 기관 이름만 표시합니다. 지도 화면은 아직 미구현입니다.
공개 목록은 한 번에 5개를 읽으며 공유 기록 더 보기로 이어서 봅니다.
모든 화면은 버튼으로 새로고침합니다. 실시간 자동 갱신은 아닙니다.

10. 철회와 변경 확인
작성자 → 공유 목록 새로고침 → 내 공유 신청의 공유 철회 → 확인.
방문자 → 공유 목록 새로고침 → 해당 사진/기록이 없어지는지 확인합니다.
작성자의 개인 기록과 사진은 유지됩니다.
개인 원본의 이름·메모·기관을 수정하거나 원본을 삭제하면 공개도 함께 철회됩니다.
수정한 내용을 공유하려면 다시 신청하고 검토를 받아야 합니다.
반려 사유는 신청자가 내 공유 신청 상태에서 확인하며 재신청할 수 있습니다.
이미 방문자가 내려받거나 캡처한 사본은 회수할 수 없습니다.
공개 사본은 HTTPS URL로 영구 노출하지 않으며 Firestore 공개 문서 제거로 새 조회를 차단합니다.

11. 오류 확인
담당자 영역 없음: 로그인한 UID와 forestReviewerGrants 하위 기관 ID/active 값 확인.
등록 기관 없음: forestCenters, 문서 ID, active boolean true 확인.
인덱스 오류: Firestore 인덱스 배포 후 생성 완료 확인.
이전 기록을 승인할 수 없음: 작성자의 원본 수정/재신청 여부 확인 후 새로고침.
일부 목록 조회 오류: 규칙, UID, 기관 ID를 확인. 오류를 빈 목록으로 오해하지 않습니다.
Firebase 무료 사용량 한도: 콘솔에서 확인. 반복 새로고침을 멈추고 사용량을 확인합니다.

이 버전은 Spark 개발용 작은 사진 사본을 사용합니다.
개인 사진·신청 사진·공개 사진 사본이 각각 Firestore 저장/읽기 사용량에 포함됩니다.
다수 기관의 운영 전에 전용 사진 저장소, 사용량 통제, 출처가 있는 식물 도감, AI 식별을 확장합니다.
