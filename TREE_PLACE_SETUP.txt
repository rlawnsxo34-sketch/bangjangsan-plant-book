v30 — 장성숲체원 나무 관찰 장소 연결

편백나무: 숙소동1 부근 난간 근처

이동 거리·방향·지도 좌표는 전달받지 않았으므로 추정해서 추가하지 않았습니다.

어디에서 보이나요?
장성숲체원 선택 → 숲 둘러보기 → 각 나무 사진 아래의 어디서 볼 수 있나요?
식물 찾기 → 해당 AI 후보 선택 → 살펴보는 방법 보기에서도 나옵니다.
다른 숲체원에서는 이 장소를 표시하지 않고 관찰 장소 준비 안내를 보여줍니다.
사진 추가·이름 선택만으로 현장 방문·관찰 표시가 자동으로 켜지지 않습니다.

적용 순서
1. 기존 프로젝트 전체를 백업합니다.
2. ZIP을 새 폴더에 풉니다.
3. 기존 public-config.json, backend/wrangler.jsonc, .firebaserc(있을 때), .git,
   src/experience-data.js와 직접 추가한 현장 자료를 보존합니다.
4. 아래 기관 ID가 맞는지 확인합니다.
5. 프로젝트 폴더 터미널에서 차례로 실행합니다.
   npm ci
   npm test
   npm run build
   firebase deploy --only hosting --project plant-book-84803
v24 공유 규칙·인덱스를 아직 배포하지 않았다면 Hosting보다 먼저:
firebase deploy --only firestore --project plant-book-84803
Firebase init·Worker 재배포는 필요 없습니다.

기관 ID 확인 (이번에 한 번 확인)
1. Firebase 콘솔에서 기존 plant-book-84803 프로젝트를 엽니다.
2. Firestore Database → 데이터 → forestCenters를 엽니다.
3. 국립장성숲체원 name을 가진 문서를 선택합니다.
4. 그 문서의 ID를 확인합니다. 기존 안내대로 만들었다면 jangseong입니다.
5. jangseong이면 수정할 필요가 없습니다.
6. ID가 다르면 src/observation-places.js를 열어 OBSERVATION_PLACES 안의
   jangseong: 부분만 실제 ID로 바꾸세요. ID에 하이픈이 있으면 따옴표로 감쌉니다.
   예: 'my-center-id': { ... }
7. 기존 forestCenters 문서 ID 자체를 바꾸거나 새 기관을 만들지는 마세요.
   기록·권한과 연결된 ID를 유지하고 이 파일의 키만 맞춥니다.
8. 저장한 뒤 다시 빌드하고 Hosting을 배포합니다.
표시 이름으로 장소를 자동 연결하지 않습니다. 기관 혼동을 막기 위해 정확한 ID로 연결합니다.

나중에 장소 설명을 수정할 때
src/observation-places.js를 열어 해당 나무의 label만 바꿉니다.
hinoki: 편백나무 / galcham-oak: 갈참나무 / japanese-maple: 단풍나무
같은 구조로 다른 기관 ID 아래에 장소를 추가할 수 있습니다.
다른 기관의 장소를 확인하기 전에는 장성의 항목을 복사해서 사용하지 마세요.
사진·식물의 일반 설명은 기존 파일에서 따로 관리하므로 변경 사항을 잃지 않습니다.
